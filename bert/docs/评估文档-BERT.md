## 4. 混淆分析

按真值分组的 top-3 预测（test 全量）：

| 真值 | 判对 | 第 2 常错 | 第 3 常错 |
|---|---|---|---|
| 无风险 | 20,572 | 信用服务 141 | 投资理财 122 |
| 投资理财 | 11,712 | 信用服务 456 | 购物服务 205 |
| 信用服务 | 4,557 | 电商客服 408 | 投资理财 199 |
| 购物服务 | 3,805 | 电商客服 538 | 投资理财 366 |
| **电商客服** | **2,862** | **信用服务 794** | **购物服务 414** |
| 领导熟人 | 1,262 | 购物服务 189 | 电商客服 71 |
| 公检法 | 1,149 | 信用服务 81 | 电商客服 41 |
| 婚恋交友 | 236 | 投资理财 119 | 购物服务 26 |
| 网黑案件 | 231 | 信用服务 35 | 电商客服 25 |
| 军警购物 | 218 | 信用服务 21 | 投资理财 18 |

**主要错误流**：电商客服 ↔ 信用服务 / 购物服务，三向互混共 1,208 条，占该类真实样本的 27.0%。

这一类三者的开场话术高度重叠（都涉及「客服」「账户异常」「退款/解冻」），
区分点在后半段（是要验证码、要保证金、还是要下载 App），而截断到 192 token
可能截掉了后半段。**这是模型容量之外的结构性问题**，加数据或换更大模型都难根治，
建议在业务侧对这三类统一标记为「客服类诈骗」再细分。

婚恋交友召回 0.516，119 条被判成投资理财——「杀猪盘」本身就是
恋爱话术引出投资，类别定义上存在包含关系。

## 6. 评估口径说明

- **抽样 vs 全量**：训练时 test 抽 12,000 条用于快速迭代（macro-F1 0.7593）；本文件用
  53,281 条全量复评（0.7621），差异 0.0028，不影响结论。
- **fastText 基线口径**：采用 `api_zh/model/metrics.json`（acc 0.8654 / macro-F1 0.7365），
  与 `fasttext/docs/评估文档-电诈识别.md` 一致。
  注意 `models_zh/metrics.json` 的重跑版本是 0.8637 / 0.7330，两者差 0.0035 是 fastText
  随机种子不固定带来的波动，不是配置差异。
- **无测试集泄漏**：dev 用于选最优 epoch，test 只在训练完全结束后评估一次。
- **切分方式**：沿用仓库既有组级切分，group 不跨 split。

## 7. 复现

```bash
# 训练（3 epoch，约 66 分钟 / RTX 3060 6GB）
python -X utf8 bert/src/train_bert_multiclass.py \
    --dataset-dir data/zh_data_process \
    --train-size 128000 --max-len 192 --epochs 3 \
    --out-dir models_zh/bert

# 全量 test 复评
python -X utf8 bert/src/train_bert_multiclass.py --eval-only \
    --dataset-dir data/zh_data_process \
    --test-size 999999 --dev-size 999999 \
    --out-dir models_zh/bert
```

随机种子固定为 42（抽样、torch、numpy 均设种子）。

## 8. epoch 数选择

| epoch | dev macro-F1 | 全量 test acc | 全量 test macro-F1 |
|---|---|---|---|
| 1 | 0.7439 | — | — |
| 2 | 0.7575 | 0.8730 | 0.7572 |
| **3** | **0.7595** | **0.8747** | **0.7621** |

dev 上 2→3 epoch 只涨 0.0020，但全量 test 上涨 0.0049，且 9/10 类改善
（婚恋 +0.021、领导熟人 +0.010、军警 +0.007，仅网黑 −0.004）。
训练时间从 49 分钟增至 66 分钟，一次性成本，值得。
