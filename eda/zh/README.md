## 口径说明：三处必须先在答辩上讲清楚

1. **10 类 vs 二分类是两套口径，不是两张数据**。二分类只是把 1~9 塌成`诈骗文本`，
   所以每张图上都标了用的是哪套；`zh01` 的图 03 讲二分类、图 01/02/04 讲 10 类。
2. **`模态` / `欺诈子类`（label_zh）两列在新数据里已经没有了**，`index.tsv` 现在实测只有 5 列：
   `split / line_no / sample_id / group / label`（10 类的中文名只在 `class.txt` 里，按行号对上）。
   旧版图 18/19 那种"短信 vs 多轮对话"的分法已经没有依据列，
   替代品是用 `group` 前缀推出的**来源形态**（`case:` → 案件切片、`txt:` → 单条文本），
   这是我自己从 group 命名的构造规则反推的口径，不是上游给的字段，答辩要说清来源。
3. **抽样口径分三种**：长度、噪声、箱线图全用训练集全量（246,403 行）；
   关键词（zh07）和词云（zh08）用 60,000 行固定种子抽样（`random_state=42`，
   35 万行跑字符 2~3gram 的稀疏矩阵会顶满内存）；条带图和散点（zh04）只画 20,000 个点，
   全量画出来是一整块黑。图上凡是抽样都会标"抽样N条"。

## 和英文侧（en/）不一样的四个地方

1. **长度口径**：中文没有空格，`str.split()` 切出来恒等于 1 个"词"，所以改成
   **字数**（`str.len()`）+ **汉字数**（正则 `[\u4e00-\u9fa5]` 计数）两个口径。
2. **分词**：材料里的中文关键词统计要用 jieba（day02 `wordcloud_custom.py`、投满分 03-fasttext
   `data_processing.py` 都有），**本机 Anaconda 目录不可写、jieba 装不上**，
   所以 zh07/zh08 改用 sklearn 自带的 `analyzer="char_wb"` 做 2~3 字字符 n-gram。
   代价：n-gram 会互相包含（"账至指"和"账至指定"各算一条），答辩要主动说明。
3. **标签本来就是中文**（class.txt 十行全中文），`label_name_map` 只做显示名，不是翻译。
4. **多了一个 index.tsv 维度**：`group`（溯源组）和由它推出的`来源形态`，
   英文侧的 group 是 MinHash 近重复组，含义完全不同——见下面第 7 条结论。

## 已跑出的结论（全部为本目录脚本在当前数据上的实测值）

1. **规模与失衡**：352,836 行，塌回二分类后诈骗 60.66%（train 60.74 / dev 60.58 / test 60.38，
   三档一致）。诈骗仍是多数类，但已经不是旧版的 75.6%——**旧结论作废**。
   → 英文侧欺诈 4.81%（少数类），中文侧 60.66%（多数类），"类别不均衡"在两侧方向相反。
   → 真实部署里骗局是少数，这个 6:4 依然和现实相反，训练侧该做类别权重或降采样。
2. **10 类分布极度不均**：最大类`虚假网络投资理财` 24.28%（train 59,819 条），
   最小类`冒充军警购物类诈骗` 0.60%（train 1,480 条），相差约 40 倍。
   → 旧版"92.8% 集中在一个类"的垄断问题已经解决，**做多分类现在可行了**；
     但尾部三类（婚恋 0.89% / 网黑 0.62% / 军警 0.60%）合计只有 2.11%，
     每类的 macro-F1 会先被这三类拖住，评估一定要按类报。
3. **manifest 30 个类×切分格子全部一致**（图 04、表 `01_manifest_reconciliation.csv`）：
   上游 `manifest.json` 声明的每类样本数和实测逐格相等，说明切分没有丢行、没有串行。
   这是数据侧交付的第一道验收，答辩先讲这条再讲图。
4. **长度**：字数 均值 144.1 / 中位 121 / P90 268 / P95 316 / P99 417 / 最大 3062；
   汉字数 中位 87 / P90 221 / 最大 2489（中位汉字数只有中位字数的 72%，差值是标点数字字母，说明话术里非汉字成分不少）。
   截断覆盖：32 字盖住 **0.25%**、64 字 15.7%、128 字 54.58%、256 字 88.17%、384 字 98.30%、
   512 字 **99.77%**、1024 字 100%。
   → 投满分的 `pad_size=32` 在中文侧只剩 0.25%，比旧版的 0.60% 更不能用；
     中文 BERT（bert-base-chinese）位置上限 512，`max_length=512` 刚好盖住 99.77%；
     fastText 没有位置上限，不需要跟着 512 走（图 15 里那条竖线只标给 BERT）。
5. **"诈骗文本更短"是混杂造成的假象（辛普森悖论，图 11 + 表 03 的"来源形态内×二分类"）**：
   整体诈骗中位 119 字 < 无风险 124 字；但**同一来源形态内部诈骗反而更长**
   （案件切片 77 vs 48 字，单条文本 164 vs 153 字）。
   原因：诈骗侧案件切片占 38.3%，无风险侧只占 28.6%，短来源把诈骗的整体中位数拉了下来。
   → 旧版这个结论靠 `modality` 列，那一列没了，但结论方向没变，依据换成 `group` 前缀。
   → 长度不能直接当分类特征用，至少不能跨来源形态用。
6. **话术成分带强类别信号**（zh06，训练集全量 246,403 行，13 条规则）：
   偏诈骗——金额收益字样 41.43% vs 5.20%、英文字母混入 62.75% vs 26.38%、
   数字串≥6位 24.68% vs 0.93%、连续重复符号 22.96% vs 1.77%、QQ/微信引流 21.83% vs 6.35%、
   网址 25.06% vs 8.03%。
   偏无风险——对话说话人标记 37.35% vs 57.44%、【】品牌/角色标记 37.47% vs 57.50%
   （无风险侧多是坐席/客户多轮文本，这两条和来源形态高度重合，不是"无风险的话术特征"）。
   对照组：全角字符 100% 命中（中文本该如此）、空文本 0 条、半角空格残留只有 2.22% ——
   说明上游清洗基本干净，而带强信号的那几条**不是噪声，删了会掉点，要留给模型**。
7. **`group` 是案件级溯源，不是近重复组——英文侧的处理方式绝不能照搬**（zh10）：
   292,825 个组，规模只有 1/2/3/4/7 五种（252,329 / 25,707 / 10,066 / 4,722 / 1），
   40,496 个多行组里 **38,844 组（95.9%）含 ≥2 个类别**，100,507 条样本（28.49%）落在多行组里。
   跨切分的组数实测 **0**（文档 §2 声明 0，对上了）。
   一个案件里同时有诈骗句和无风险句是**设计如此**（案件有前有后），不是标注冲突。
   → 英文侧的规则是"组内标签冲突→整组剔除"，中文侧照做要扔掉 28.49% 的数据，属于自毁。
   → 但多行组确实让同一案件的多条文本散落在训练集里，评估时同溯源组内要一起看，
     不能按单条算独立样本（这一点是中文侧目前留下的真实风险）。
8. **完全重复 0，但模板家族不是 0**（zh09，图 22/23）：
   三份切分内部逐字重复各 0 行，同一条文本跨切分 0 例——文档声明吻合。
   但把可变槽位抹掉做"骨架归一"（数字→N、网址→U、【】→B、去标点）后，
   352,836 行只剩 352,544 个骨架（平均 1.00 条/骨架），其中 **88 个骨架跨了 ≥2 个切分（0.0249%）**，
   最大的家族 17 条，横跨 3 个切分、含 5 个类别，前三名都是
   `为了确保您的账户安全…请点击以下链接…U` 这一类钓鱼模板。
   → 文档只承诺了"完全重复 0"，没承诺骨架级；这 88 个是自查查出来的、占比极小但确实存在的泄漏面。
   → 答辩说法：**"重复率0%"这句要加限定——逐字重复为0，模板级近重复为0.025%。**
9. **高频信号串**（zh07，60,000 行抽样，字符 2~3gram，lift = 组内出现率/组外出现率）：
   偏诈骗 `向指定` / `账至指` / `元到` / `，检测` / `钱之`（转账指向 + 到账金额 + 假检测）；
   偏无风险 `醒您在` / `如果` / `轻信` / `联系官方` / `提供正` / `在官方`（提醒 + 正规渠道）。
   → 欺诈侧全是"收益+转账+催促"，无风险侧全是"提醒+核实"，两类风格差异大到能被 n-gram 抓住，
     这正是"传统模型也能做这个任务"的证据，也是特征工程该保留哪些词的清单。

## 已知不完美（被追问时主动交代）

- `来源形态` 是我从 `group` 前缀反推的，上游没有这一列，`config.py` 里 `group_kind_name_map`
  用 assert 锁死了"前缀只能是 case/txt"，真出现第三种前缀脚本会直接报错而不是悄悄画错。
- zh08 词云在本机跑不出来（wordcloud 装不上），图 21 是空的；高频词表已经落 CSV，
  换一台能装库的机器跑同一个脚本就能补上图。
- zh07/zh08 是 60,000 行抽样，绝对次数和全量对不上，但 lift 是比率，抽样不影响排序。
- 骨架归一是正则槽位替换，不是 MinHash+LSH。它只能抓到"换了数字和品牌名"的同模板，
  抓不到"改了句式"的近重复；英文侧那边才是 MinHash，两侧口径不同别混着说。
