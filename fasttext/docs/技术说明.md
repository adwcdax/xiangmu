# 技术说明

## 1. 目标与范围

判断一条招聘广告是否为**欺诈岗位**（二分类：`legitimate` / `fraudulent`），并给出可解释的
结构化证据（是否缺少公司 Logo、公司简介、薪资区间等）。

适用域：英文招聘广告（EMSCAD 分布）。模型输出为概率，业务侧按阈值转成"推送/不推送"，
定位是**辅助审核排序**，不作为自动处罚依据。

## 2. 数据来源与处理链

```
data/raw/fake_job_postings.csv        17,880 行 × 18 列，欺诈 866 条（4.84%）
        │  data_process.py：清洗 description、近重复归组、组级分层切分
        ▼
data/data_process/{train,dev,test}.txt   14,276 / 1,785 / 1,785（欺诈 687 / 86 / 86）
        │  src/prepare.py：小写、HTML 还原、NFKC、空白归一，转 __label__x 前缀
        ▼
models/data/{train,dev,test}.txt         14,274 / 1,785 / 1,785（2 条空正文被跳过）
        │  src/prepare_features.py：拼结构化字段 token
        ▼
models/data_feat/{train,dev,test}.txt
```

- 清洗只保留 `description` 字段作为正文，其余字段单独转成 token（见第 4 节）。
- 指纹与清洗记录：`data/data_process/manifest.json`。
- 复现链：`data_process.py` 可完全重跑，输入指纹写在 manifest 里。

## 3. 为什么必须按"近重复组"切分

EMSCAD 里同一份 JD 会被反复爬取（改写标题、重复投放）。若逐条随机切分，同一份帖子的副本
会同时落进训练集和测试集，指标会虚高。

`data_process.py` 的做法：

1. 完全重复文本先并组；
2. MinHash（128 perm）+ LSH（16 bands × 8 rows）找候选对，精确 Jaccard ≥ 0.75 复核；
3. 并查集归组，**按组**做 8:1:1 分层切分；
4. 组内标签冲突的样本剔除（5 组 34 条）。

事后自检（`leakage_report.json`）：`groups_crossing_splits = 0`、`exact_texts_crossing_splits = 0`。

**这个改动的影响很大**：旧切分下测试集有 40.5% 的样本能在训练集里找到近重复，
欺诈 F1 报出 0.80；按组重切后同一模型只有 0.30~0.40。真实水平以后者为准。

## 4. 特征工程

### 4.1 正文

`description` 经 `html.unescape → NFKC → 空白归一 → 小写` 后直接作为 fastText 输入；
英文按空格自然分词，不需要额外分词步骤。

### 4.2 结构化字段 → token

用 `data/data_process/index.tsv` 里的 `job_id` 与 raw CSV 对齐，逐行追加：

| 来源字段 | 生成的 token |
|---|---|
| `has_company_logo` | `f_nologo`（缺失时） |
| `company_profile` | `f_profile_empty` / `f_profile_short`(<120 字) / `f_profile_long` |
| `salary_range` | `f_salary_missing` |
| `telecommuting` | `f_remote` |
| `has_questions` | `f_no_questions` |
| `employment_type` | `f_emp_{full_time,part_time,contract,temporary,other,na}` |
| `required_experience` | `f_exp_{entry_level,mid_senior_level,associate,director,executive,internship,not_applicable,other,na}` |
| `required_education` | `f_edu_{bachelor_s_degree,...}` |
| `industry` | `f_ind_{top25 行业}`，其余 `f_ind_other` |
| `function` | `f_fn_{top25 职能}`，其余 `f_fn_other` |

行业/职能的 top25 只在**训练集**统计，快照落盘为 `api/vocab.json`，推理端复用，避免取值漂移。

### 4.3 正文派生 token

| 规则 | token |
|---|---|
| 含邮箱 / URL | `f_email` / `f_url` |
| 数字个数 >30 / 5~30 / ≤5 | `f_digits_many` / `f_digits_some` / `f_digits_few` |
| 大写字母占比 >8% | `f_upper_high` |
| 正文长度 <600 / 600~1500 / >1500 | `f_len_short` / `f_len_mid` / `f_len_long` |
| `!` ≥3 次 | `f_bang` |

## 5. 模型与超参

fastText 监督分类（`train_supervised`），最终配置（按 dev PR-AUC 从 3 组里选出）：

```python
dim=50, epoch=25, lr=0.5, wordNgrams=2, bucket=200000,
minCount=2, loss="softmax", ws=5, neg=5, seed=20261021
```

- 正例占 4.8%，训练时**正例重复 3 次**（等价类别权重）。消融显示 ×1 / ×3 / ×5 的 PR-AUC
  差别很小，但 ×3 的召回更好。
- 模型体积 49.0 MB，训练耗时约 7 秒（14k 条，32 线程）。

## 6. 评估

### 6.1 指标选择

测试集正例率 4.82%，"全判正常"的准确率就有 **0.9518**，所以准确率没有区分度
（模型实际 0.9535~0.9602，只高 0.2~0.8 个百分点）。看三个指标：

- **PR-AUC**：阈值无关的排序能力；
- **欺诈 F1 / 精度 / 召回**：业务可解释；
- **Top-K 命中率**：和人审产能直接对应。

### 6.2 消融（test，1,785 条 / 86 正例）

| 方案 | PR-AUC | 阈值 | 精度 | 召回 | F1 |
|---|---|---|---|---|---|
| 仅正文 | 0.4266 | 0.05 | 0.500 | 0.314 | 0.386 |
| **正文 + 字段** | **0.5457** | **0.09** | **0.597** | **0.465** | **0.523** |
| 仅字段 | 0.3770 | 0.38 | 0.329 | 0.547 | 0.410 |

两个结论：
1. 补字段让 PR-AUC 提升 28%（相对），召回 0.31 → 0.47；
2. **只用字段就有 0.41 的 F1**，说明欺诈信号很大一部分在"资质完整性"上，不只在文案。

### 6.3 推送效果（正文+字段模型）

| 推送量 | 命中率 | 覆盖诈骗数 |
|---|---|---|
| Top-20 | 0.95（19/20） | 19 / 86 |
| Top-50 | 0.66（33/50） | 33 / 86 |
| Top-100 | 0.47（47/100） | 47 / 86 |

### 6.4 阈值怎么定

阈值只在 **dev** 上选，再原样套到 test。当前 0.09 是 dev 上 F1 最优点。
若业务更怕误伤，抬高阈值（0.5 时精度 0.80、召回 0.23）；更怕漏报则压低。

## 7. 已知局限

1. **召回偏低**：阈值 0.09 时只覆盖 47% 的诈骗。正文写得规范、公司信息齐全的诈骗帖识别不出来。
2. **样本量小**：test 只有 86 个正例，指标波动约 ±0.05，跨批次对比要谨慎。
3. **词袋模型的固有上限**：fastText 看不到语序和长距离语义，"先交押金"和"押金先交"对它几乎等价。
   进一步提升需要换 BERT 类模型。
4. **分布漂移**：训练数据是 EMSCAD（2012—2017 年英文招聘站），换成其他平台/语种需要重新评估。
5. **字段依赖**：推理端若拿不到结构化字段，会被当成"全部缺失"，把正常岗位推向欺诈。
   这是接口层的硬约束，见 API 文档。

## 8. 复现与版本

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -X utf8 src/prepare.py
.venv/Scripts/python.exe -X utf8 src/prepare_features.py
.venv/Scripts/python.exe -X utf8 src/train.py --data-dir models/data_feat --model-dir models
```

- Python 3.12.10；fasttext-wheel 0.9.2；numpy 1.26.4（必须 <2）。
- 随机种子 20261021；数据切分种子 20261020。
- 产物：`models/fasttext_en_feat_os3.bin`（不入库）、`models/metrics.json`（多组超参对比）。
